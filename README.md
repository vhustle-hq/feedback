# Vhustle feedback

The public place to report bugs and request features for the Vhustle app and website. Vhustle's code is private; this repository holds issues only.

**[Open an issue →](https://github.com/vhustle-hq/feedback/issues/new/choose)**

## What belongs here

- Bugs in the Vhustle app (iPhone or Android), the website or our emails.
- Feature requests and ideas to improve Vhustle.

## What doesn't

| Topic | Where it goes |
|-------|---------------|
| Security problems | [Report privately](https://github.com/vhustle-hq/feedback/security/advisories/new). Never in a public issue. |
| Your account, subscription, refunds, privacy or data deletion | **You → Help** in the app. Never post account details here. |
| Medical or injury questions | A doctor or qualified professional. Vhustle is not medical advice. |
| General questions | **You → Help** in the app. |

## Rules

Issues that break these rules are closed without a reply.

1. **Use a form.** Blank issues are turned off. Pick *Bug report* or *Feature request* and fill in every required field.
2. **Search first.** If your bug or idea already has an issue, add a 👍 reaction to it instead of opening a new one.
3. **One problem per issue.** Two bugs means two issues.
4. **No personal data.** Don't post your email, phone number, account ID, or your health data (weight, food, sleep, heart rate). Crop or blur screenshots before you attach them.
5. **No "+1" or "any update?" comments.** Use the 👍 reaction. Comments that add nothing are hidden.
6. **Write in English** so everyone can follow.
7. **Be respectful.** Our [code of conduct](https://github.com/vhustle-hq/.github/blob/main/CODE_OF_CONDUCT.md) applies everywhere.
8. **No pull requests.** The code isn't here, so pull requests are closed.

## How we track issues

Every issue carries one **status** label. Only maintainers set labels.

| Status | Meaning |
|--------|---------|
| `status: needs-triage` | New. We haven't reviewed it yet. Every new issue starts here. |
| `status: needs-info` | We asked you a question. Issues with no reply for 21 days are closed. |
| `status: confirmed` | We reproduced the bug, or we agree the idea fits Vhustle. |
| `status: planned` | It's scheduled for a coming release. |
| `status: in-progress` | Someone is working on it now. |
| `status: fixed` | Done. The issue closes when the release that includes it ships. |
| `status: wont-fix` | We decided not to do it. We explain why before closing. |
| `status: duplicate` | Already reported. We link the original and close this one. |

Other labels say what kind of issue it is (`type: bug`, `type: feature`), where it happens (`platform: ios`, `platform: android`, `platform: website`, `platform: email`) and which part of Vhustle it touches (`area: train`, `area: recover`, `area: sleep`, `area: fuel`, `area: vee`, `area: friends`, `area: pro`, `area: account`).

When an issue needs engineering work, we track it internally and add `tracked`. The public issue stays open until the fix ships, so you can follow it here.

Closed issues are locked after 30 days. If the problem comes back, open a new issue and link the old one.
